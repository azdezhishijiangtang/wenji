# 文几 · 语文能力训练站

线上：https://azdezhishijiangtang.github.io/wenji/

不把语文做成题库，而把它拆成四个底层动作：**辨异、结构、转化、积累**。六个训练器是这些动作的应用场，不是目的；考试只是它们的抽样。

本项目是《碳基学习引擎·双站建设方案书》的第一个落地站点：语文站。引擎逻辑（队列、FSRS、掌握度、校准、错因、周报、能力诊断）严格隔离在 `src/engine/`，页面只通过引擎的读写入口打交道；以后把本地存储换成服务端 API，页面不需要重写。

## 快速开始

站内使用说明：打开站点后点顶栏「说明」，或直接访问 `/#/guide`。

```bash
git clone https://github.com/azdezhishijiangtang/wenji.git
cd wenji
npm install
npm run dev          # http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build
npm run preview
```

测试：

```bash
npm test             # 51 个测试：内容 lint + 引擎纯逻辑 + 诊断 + 全路由渲染冒烟
```

首次打开会自动写入 266 个条目、59 个模型。数据只存在当前浏览器的 `localStorage`，没有账号、没有服务器、没有上报。换设备用「设置 → 数据 → 导出 JSON」。

## 引擎三件套：变式、抽样、转化

- **变式生成器**（`/drills/variant`）：补上 `mastery.ts` 里欠的账——AI 按模型定义生成 3 道变式选择题（换壳不换核），过 `lintVariantDraft` 质检 + 人工确认后入库，`variant_level: 2`，与种子条目同权走队列 / 掌握度 / 校准。AI 只出题，不判定“学会”。
- **限时抽样卷**（`/exam`）：把“考试只是它们的抽样”从口号变成动作。从已学条目按六维配比抽 6/10/14 条、开卷计时、逐条跳转作答；作答仍走 `submitReview` 全链路，交卷只产生一张验收快照。
- **积累簿转化回看**：日课写下那句话的约 3 天后，今日页出现转化卡——造新变体 / 压到一半 / 换反例，转化对象是当时的快照；FSRS 驱动回看节奏，“积累”从此有“化”。

## 根本能力：先练底层动作

语文的“玄学感”，多半来自把能力混在题型里。这里把底层动作单独拎出来：

1. **辨异**：一个词的范围、程度、预设、语气变了，句子的意思就变了。阅读的“理解”首先是辨异，写作的“准确”也来自辨异。
2. **结构**：句子的顺序就是思路的顺序。连接词、指代、因果、转折、收束，决定一段话能不能成立。
3. **转化**：同一意义在概括、展开、改写、压缩之间移动。能转化才是真懂，只会复述是假懂。
4. **积累**：文言词、意象、手法、名篇。积累不是背诵量，而是“可调用性”。

「基本功」页把前两项做成可以每天练的动作：

- **辨异 10 题**：两个词都能进句子，先选，再用一句话说出差别，最后才看语义轴；不做“背释义”的选择题。
- **重组 6 题**：把打乱的句子排成一条思路，提交后看连接词为什么各就各位；不按题型给模板。
- 每题仍然走同一套引擎：把握度、FSRS、掌握度、能力诊断。基本功不是法外之地。

## 六个应用场

| 训练器 | 底层动作 | 机制 |
|---|---|---|
| 语义分辨 · 挖词 | 辨异 | 议论文段挖 6–8 个程度/范围/转折/因果/指代/模态词，5 选 1；答后给原文证据与语义轴 |
| 篇章逻辑 · 论证 | 结构 | 先逐句标结构（论点/论据/推理/让步/反驳/结论），再判断干扰句属哪类谬误 |
| 文言积累 | 积累 | 42 条词义、认读 + 回译双卡；例句全部标出处，走 FSRS |
| 表达转化 · 写作 | 转化 | 20 分钟写 150–300 字；本地规则逐句标注 + 断点 + 追问；可选 AI 诊断，只诊断不代写 |
| 文本感受 · 鉴赏 | 辨异 + 积累 | 30 个手法、40 组意象卡片；每日精读 + 不少于 10 字批注，AI 只点评批注 |
| 句法控制 | 结构 | 现代文找主干；文言断句，每个断点必须给出依据 |

## 日课：日积月累不是打卡

每天从内容库里固定抽取三样：一个文言词义、一个意象、一个手法，再轮换一篇精读（诗/散文/小说）。它们不计分、不进入掌握度；真正计入“日课”的只有你写下的那一句（≥10 字，具体到词、句或判断）。

- 三样按日期稳定：同一天刷新不变，换一天才换。
- 积累簿保留最近 14 天，进入能力诊断的“积累证据”。
- 日课不是训练的替代品：只读不写、只看不作答，都不会被算成完成。
- AI 复盘由你手动触发，不会后台跑。

## 能力诊断：用证据说话

六维：语义分辨、篇章逻辑、文言积累、句法控制、文本感受、表达转化。基本功的作答会并入“语义分辨”与“篇章逻辑”，不另开一个孤立分数。

- **综合指数**不是考试分数，而是行为证据的压缩：掌握度 35% + 近 30 天正确率 25% + 覆盖 20% + 校准 20%。
- 只在一个维度有作答时，不给综合分（避免用 1 个样本假装全局）；样本不足会标“证据不足”。
- **写作不折算成分数**：写作没有客观对错，本站只记录草稿、结构断点与修改，不把 AI 评语伪装成分数。
- 每次诊断会指出“最稳的维度 / 最该补的维度 / 一个具体动作”，并列出诊断依据（多少条作答、多少个学习日、多少天日课、多少份草稿）。
- 最近错题可点“AI 追问”：AI 只指出一个冲突点并追问，不给正确答案与完整解析。

## 引擎规则（硬编码，不靠提示词）

- **先试后看**：所有计分作答先选把握度，提交后才显示答案与解释；没有“看答案”按钮。
- **做题算复习**：队列只认 `reviews` 事件；浏览词典、翻看解析、只读日课不计完成。
- **闭卷验证**：掌握度只由作答数据驱动，页面上没有“标记已掌握”。
- **不代输出**：AI 只做诊断、挑错、追问；写作页不提供范文、不评分、不改写。
- **达标即停**：模型到 LV.3 后，队列不再主动推新条目（`skipped_variants` 会计数），只保留 FSRS 到期复习。
- **FSRS-6**：间隔全部由 `ts-fsrs` 计算，没有 1/2/4/7 天手写序列。
- **队列上限**：默认每日 40 条、新卡 12 条；到期优先，逾期越久越前，高估模型加权；按题组整组放行，避免把一段文本拆碎。
- **校准**：作答前 5 档把握度（10/30/50/70/90），强制选择；`bias = 平均把握 − 正确率×100`，样本 <5 不下结论；高估榜 >+20，低估榜 <−20。
- **错因冷静期**：错题当天不打标，次日才出现六类错因面板。
- **48 小时回队**：挖词错空延迟 48 小时再进队列（同空位，不伪造“不同挖空位”）。
- **夜间模式**：23:30–06:00 队列清空、不推送新任务；仍可从「训练」自选练习，作答正常记录（系统不鼓励熬夜，但不锁死）。
- **不展示刷题量**：仪表盘只展示达标模型数、校准偏差、连续学习天数、省下的重复练习等资产型指标。

## 掌握度

五档：未接触 → 初识 → 会用 → 熟练（达标线）→ 自动。

- 任意首次作答进入 LV.1；
- 同一模型下 **3 道不同条目**连续答对升一档，同一条目重复答对不计连对；
- 升档同时要求校准偏差 ≤ +10（没有明显高估）；
- 答错立即降一档，连对清零；
- LV.3 起停止主动推送新条目。

## AI 接口

默认关闭。设置里填 OpenAI 兼容接口的 `baseUrl`、`model`、`apiKey` 即可。Key 只存本机 `localStorage`，请求由浏览器直连你填的地址，本站没有后端中转。

AI 用在五处，全部手动触发：

1. 写作结构诊断（JSON Schema 校验，失败重试一次，仍失败就报错，不降级为自由文本）；
2. 精读批注点评（只评批注，不重写）；
3. 错题追问（只指出冲突并追问，不给答案）；
4. 每日复盘（只根据当天数字与日课写 20–260 字，不空泛表扬）；
5. 能力深度诊断（只解释本地算好的证据，不编造分数/排名，不承诺提分）。

## 与方案书的偏离（请先读）

这是有意的裁剪，不是遗漏：

1. **单站、本地优先**：没有 Postgres、没有服务端、没有统一账号。三张表的结构与只增不改的 `reviews` 保留在本地 DB 里；`src/engine/store.ts` 是唯一写入口。以后接服务端时，替换这一层即可。
2. **没有 LLM 变式生成器**：内容全部预置、可审计；“变式”来自同模型的不同条目，而不是假装生成。因此掌握度用“不同条目连对”代替方案书的 `variant_level` 门槛，否则大多数模型会永久卡在 LV.1。等真正的生成器上线，再换回按难度门槛累计。
3. **错空 48 小时回队是同空位**：不伪造“同段不同挖空位”。这是目前最明显的一处未达标，已在代码注释和这里标明。
4. **T6 是“找主干 + 断句”**，不是完整的成分标注树；先保证句级结构感可训练，再谈逐层标注。
5. **周报按需计算**：打开档案页时计算最近 7 天，不依赖“周日 21:00”的定时任务；本地静态站没有常驻进程。
6. **AI 只解释、不判定**：判分、调度、掌握度、能力指数全部本地计算；AI 输出永远不写回 `reviews` 或掌握度。
7. **逐空即时反馈**：挖词不是整段提交后统一对答案，而是每空提交即反馈——反馈越近，修正越有效。
8. **把握度是 5 档 chip**，不是 0–100 连续滑条：降低操作成本，同时避免默认 50 污染校准数据。
9. **能力指数是行为代理，不是高考估分**：它只能说明“哪些能力有可验证证据、哪些还空着”，不能预测卷面分数。
10. **新增了方案书没有的“基本功”**：辨异与重组不是题型，而是阅读/写作的共同底层动作；它们并入原有能力维度，不另造一套评分。

## 内容与数据

- 基本功：辨异 10 题、重组 6 题。
- 应用场：挖词 5 篇 / 36 空；论证 5 篇 / 29 句 / 20 个判断句；文言 42 条（24 个虚词义项覆盖 18 个虚词 + 18 个实词，含双卡）；手法 30、意象 40、精读 4；主干 6、断句 5；写作 6 题。
- 所有解释都带原文证据；`content.test.ts` 会校验 evidence 是填回答案后的原文子串、候选唯一、答案在候选里、每个 `model_tag` 都有定义。
- 导出文件是纯 JSON（`version: 1`），会抹掉 AI Key，可直接导入另一台设备；导入会做版本校验，旧备份会自动补齐新的 `daily` / `coach_reports` 字段。

## 已知限制

- 没有浏览器端到端测试（本机没有 Chromium）；已有 jsdom 全路由渲染冒烟，交互仍建议人工过一遍。
- 能力诊断的样本门槛不高：10 条以下会标“低置信”，但页面仍会给出方向性描述，别把它当结论。
- 日课内容会随日期轮换，42 个文言义项、40 组意象、30 个手法循环使用；扩充时改 `src/content/` 即可。
- 文言 42 条只是起步集，离方案书的 220+ 张还有距离；扩充时只需往 `classical.ts` 加条目，seed 会自动生成双卡。
- 写作诊断的本地扫描是规则启发式，不判断论证质量；它的价值是逼你看见结构断点，不是给分。
- 变式生成依赖 AI 接口与人工确认；未启用 AI 时工坊只显示已有变式，质检规则（`lintVariantDraft`）在本地运行，不依赖 AI 可用性。
- 到期队列按题组整组放行（组感知装入）：放不下的整组顺延并在今日页标注数量；组本身超过每日上限时才截断。
